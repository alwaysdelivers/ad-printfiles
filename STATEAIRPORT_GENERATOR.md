# STATE-AIRPORT GENERATOR — Reconstruction & Regeneration Protocol
_Companion to STATE_BUILD_PROTOCOL.md. Proven 2026-07-20 by pixel-reproducing tx-dfw._

## Why this exists
The airport print files (STATEAIRPORT_*) were generated by an in-session Python tool that
was NEVER committed. When new airports are needed, the generator must be reconstructed.
This document stores the exact, verified process so it never has to be reverse-engineered again.

## Anatomy of a state-airport print file (verified from tx-dfw / tx-aus / ny-jfk / ny-lga)
Canvas: **3600 x 4800** transparent PNG. Three stacked layers, all centered on x=1799 (canvas center 1800):
1. **STATE GHOST** — the 2-letter state abbrev (e.g. "TX", "CA") in **Monoton**, faint.
   - Color = the token's STATE color (see tokens). fc_light ghost = red #c03018.
   - Opacity: **50%** (alpha 127) on fc_light/light; **75%** (alpha 191) on dark tokens.
   - Size: **Rule B** — fit natural bbox within a **3000 x 1701** box: scale=min(3000/w,1701/h).
     For 2-letter codes the WIDTH binds (~3000 wide).
   - Placed: horizontally centered; top at **y=900** (block top = 3.00in).
2. **AIRPORT CODE** — 3-letter IATA (e.g. "DFW","LAX") in **Monoton**, solid.
   - Color = token CODE color. fc_light code = navy #1e3a5f (RGB 30,58,95).
   - Box (measured, DFW): **w≈2730 h≈827**, top at **y≈1337**, centered x=1799.
     (Code is scaled to fit this box; 3-letter codes land ~this size.)
3. **LOCKUP** — the standard _ALWAYS DELIVERS sprite, **pasted VERBATIM** (never re-rendered).
   - Extract from an existing shipped file's lower zone (y>3200).
   - Sprite size 2187x613; placed at **x=706 y=3314** (tee), **x=1006 y=3314** (hoodie).
   - Recolored/opacity already baked per token in the source file — extract the matching token.

## Tokens (4, LOCKED) — filename: STATEAIRPORT_{code}-{airport}_{token}_{garment}.png
- **fc_light**       — light garments; ghost 50%, state=red, code=navy.  (only light token)
- **redstate_white** — dark garments; state 75%, code 100% white.
- **neonstate_white**— dark garments; state 75% neon blue, code 100% white.
- **goldstate_white**— dark garments; state 75% gold, code 100% white.
NEW builds carry NO _r2 suffix (only legacy tx- files do).
Each airport = 4 tokens x 2 garments (tee/hoodie) = 8 print files (+ web/webp twins).

## Fonts
Monoton-Regular.ttf (Google Font):
  https://github.com/google/fonts/raw/main/ofl/monoton/Monoton-Regular.ttf
Fetched fresh each session (not committed).

## §8 PROOF GATE (mandatory before shipping any new state)
Before generating a new state, REPRODUCE a known-good reference (tx-dfw fc_light tee) and
confirm the composite bbox matches x[301..3298] y[900..3919] within ~1px on all edges.
Only proceed once the repro matches. (Verified match 2026-07-20.)

## Generator (verified working — gen_core.py)
See gen_core.py in this folder. Key functions:
- render_monoton(txt, target_w, target_h, fill): renders text in Monoton scaled to fit a box.
- compose(ghost_txt, code_txt, ghost_rgb, code_rgb, ghost_alpha, lockup_img, lockup_xy, code_box):
  composites the 3 layers on the 3600x4800 canvas.
Extract lockups first via extract_lockup2.py (per token x garment).

## To build a NEW state (e.g. CA: LAX SFO SAN SJC SMF SNA)
1. Fetch Monoton. Extract the 8 lockups from tx-dfw (extract_lockup2.py).
2. Run §8 proof gate (reproduce tx-dfw). Confirm match.
3. For each airport code, each of 4 tokens, each garment:
   compose(ghost='CA', code='LAX', <token colors/alpha>, <token lockup>, <tee/hoodie xy>, code_box)
4. Save print PNG (3600x4800). Generate web + webp twins.
5. Verify each output bbox ≈ x[301..3298] y[900..3919].
6. Push to printfiles/stateairport/ and printfiles/web/stateairport/.
7. Wire per STATE_BUILD_PROTOCOL §0.5 STEP 4-8 (product Style options, section styleOrder/treatUrl,
   fulfillment routing, chips).

## Token color reference (measured from shipped fc_light; dark tokens from red/neon/gold files)
- fc_light:  ghost=#c03018 @50%, code=#1e3a5f @100%
- redstate_white:  state @75% red,  code white @100%
- neonstate_white: state @75% neon, code white @100%
- goldstate_white: state @75% gold, code white @100%
(For dark tokens, extract exact hexes from an existing dark-token file before building.)

## FIX 2026-07-20: code scaling
Codes are rendered at a FIXED font size (1025), NOT fit-to-box, then baseline-anchored
(bottom at y=2164). Fit-to-box wrongly shrank narrow codes. Fixed size reproduces DFW
exactly (w=2730 h=828) and keeps all codes at consistent letter height. See gen_core.py.
